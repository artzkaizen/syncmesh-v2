## Context

The third tier is declared and inert. `visibility: "authority"` exists in the manifest, maps to
partition kind `global`, and its entry shape forbids an `allow` block. `checkPolicy` carries an
`isAuthority` skip that no live path reaches. Nothing gates anything: a relay does not evaluate
who receives which rows, and a device folds every row it is sent.

It was attempted on 2026-08-28 and rejected. Six problems were confirmed, and the note that
recorded them named the root cause: **the tier was built as validation when it is admission.**

That distinction is the whole decision. A validation rung asks *may this write happen*, and every
device runs it, which is why every device reaches the same verdict. Admission asks *does this
event enter this device's log at all*, and only the authority can answer it, because the answer
is computed from a database no device holds — clinic membership, `status = "signed"`, whether the
consult window is open (`plan/use-cases.md` §4).

Building the second as the first is what produced problem 1: giving the tier an `allow` block
turned the dormant `isAuthority` skip into the live path, so a device folded and kept a write the
authority quarantined, with no correction path, because the authority never accepted the event.
Two devices, same events, different rows. The test blessed the split rather than catching it.

## What has changed since the rejection

**Problem 4 has an answer now.** It was recorded as *"a withheld event stalls that author's whole
stream, because holdback releases only a contiguous run and nothing ever fills the gap; the gated
tier needs a sequence of its own."*

That is D23 exactly, and D23-A shipped: a sender that filters hands back the contiguous reach of
the **unfiltered** run it scanned, and the receiver adopts it — folding what the pages did deliver
before the cursor moves past the hole, and treating a widened scope as a re-join. Admission is
the same shape as interest with a different predicate: filter at the sender, then say how far the
scan reached. The gated tier does not need a sequence of its own; it needs the coverage D23
already carries, with a scope that names the entitlement rather than the interest.

That leaves five problems, and three of them (2, 5, 6) are consequences of the first: `can()` and
`validate()` disagree because there is a local verdict at all; `startRelay` gates nothing because
the option was never plumbed; a synced `_policy` cannot govern the tier because the rejected
design guaranteed its events carried no partition. Fix the framing and 2 and 6 stop existing; 5
is plumbing.

Problem 3 stands on its own and is the reason this needs a decision rather than a patch.

## Options

- **A · The authority is the only author.** A device never writes a gated table; it asks, and the
  authority writes. Reads are an admitted subset, held offline like any other rows once the
  authority has spoken. `can()` answers *not here*, honestly, because there is nothing local to
  evaluate. One author means one verdict and no split to converge.
- **B · Devices author, the authority admits, a refusal is a correction.** Writes stay offline-first
  and optimistic; the authority admits or refuses on arrival, and a refusal travels as an E16
  correction the device folds. Keeps the offline story whole and reuses machinery that exists.
- **C · Gated tables are not synced rows at all.** They are read through the relay as a live query
  (E27's row path) and never enter a device's log. No admission problem, because nothing is
  admitted; no offline, because there is no log.

## What the research points to

**A**, with B available later as an additive change.

The use-case table already says what the tier promises: *may read: the app's database*, *offline:
**after the authority has spoken once***. That sentence describes reads. It does not promise
offline writes, and A gives up only what was never claimed.

A also collapses the three consequential problems rather than managing them. There is no local
verdict, so `can()` and `validate()` cannot disagree; there is nothing for a synced `_policy` to
govern on a device, so problem 6 is not a gap but the design. And the one rule that has cost this
repo most — *a verdict may never depend on something only one peer holds* — is satisfied by
construction rather than by care, because no peer but the authority reaches a verdict at all.

B is where this should end up, and the reason not to start there is problem 1's shape. Optimistic
local writes plus authority refusal is precisely the split that was rejected, made safe by a
correction path. Building the correction path first, against a tier with one author, is how that
gets tested before anything depends on it.

C is the honest answer for a table that is genuinely a server view, and E27 is where it belongs.
It is not this tier: the use case wants these rows in a clinic phone's pocket on a train.

## Watch out

- **Problem 3 is not solved by any of these, and must be, before anything ships.** The rejected
  design guaranteed `event.partition === undefined` for the tier, and `matchesInterest` refuses an
  unpinned event against any interest naming partitions — so rows meant for every device reach
  none of the devices that narrowed. Either the tier's events carry a partition after all, or
  `matchesInterest` and `rowsIn` learn that an unpinned row belongs to every interest. The second
  needs a convergence argument of its own: two devices with different interests must still agree
  on which rows they hold, and "belongs to everything" is a claim about every future interest too.
- **An admitted subset is a scoped cursor** (D23). Whatever the relay withholds, it must say how
  far it scanned, and the scope must name the entitlement — not the interest — or a device whose
  entitlement widens keeps a cursor that silently skips everything it was not allowed to see when
  it was narrower. This is the same failure as widening an interest, with worse consequences.
- **`startRelay` must reach the gate.** The rejected attempt left the option unable to reach a
  room, so it was testable only through `openRelayRoom` and fanout ingress bypassed it entirely.
  A gate a fan-out can walk around is not a gate.
- **Two devices with the same entitlement must be admitted the same set.** An admission decision
  that reads a clock, or the order rows happened to arrive at the relay, is the divergence class
  this repo has shipped seven times — and here it would be invisible, because each device would be
  behaving exactly as it was told.

## Decision

**A.** The authority is the only author of a gated table. A device reads an admitted subset and
holds it offline; a write to such a table is refused with a typed value, because there is nothing
local to evaluate and never was. B stays available as an additive change once the correction path
it needs has been built and tested against a tier with one author.

The rule this buys, and the reason it is worth giving up an optimistic write for: **no peer but
the authority reaches a verdict at all**, so the split that produced problem 1 is not managed, it
is unrepresentable. `can()` answers *not here* honestly. `checkPolicy`'s `isAuthority` skip goes
away rather than going live, and with it problems 2 and 6 — there is no local rule for `can` and
`validate` to disagree about, and nothing on a device for a synced `_policy` to govern.

**Problem 3 is settled here, because it turned out not to be about this tier.** An unpinned event
matches **every** interest, on the partitions dimension alone.

That is a bug fix, not a concession. `matchesInterest` refuses an unpinned event against any
interest naming partitions, so a `global` table — whose entire promise is *replicated to every
device* — already reaches every device **except** the ones that narrowed. The catalog is invisible
to exactly the devices that were careful. The gated tier would have inherited that; it did not
cause it.

The convergence argument is that there is nothing to converge. An interest naming instances says
*only rows in these instances*, and an unpinned row is in no instance — it is about the mesh, not
about an instance, which is what being unpinned means. Excluding it reads the clause as *only rows
that are in some instance and it is one of these*, which is a different sentence and not the one
anyone wrote. Two devices with different interests both receive every unpinned event, so they
cannot disagree about one; and the `tables` dimension still excludes what a device does not want,
which is where a device that wants less should say so.

Three things this settles that must hold together:

- **A gated table's events are authored by the authority and by nobody else**, checked on
  authorship exactly as `global` already is — never on a local flag, because the same event must
  reach the same verdict on every peer.
- **An admitted subset is a scoped cursor** (D23). The relay says how far it scanned, and the
  scope names the **entitlement**, not the interest, or a device whose entitlement widens keeps a
  cursor that silently skips everything it was not allowed to see when it was narrower.
- **The gate must be reachable from `startRelay` and unavoidable by fan-out.** The rejected
  attempt left the option unable to reach a room and let fanout ingress past it; a gate a fan-out
  can walk around is not a gate.
