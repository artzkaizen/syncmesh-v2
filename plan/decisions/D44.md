---
id: D44
title: A gated room checks blob puts and fetches against the socket's grant
status: decided
decided: A
epics: [E15, E24]
---

## Context

D40 gates a room's rows by grant: a socket is served the partitions its verified grant covers.
Blobs were left outside that gate (E15):

- **Puts.** `blob-put` carries the partition the bytes are billed to, as the putter's claim. The
  relay does not check it, so one socket can fill another partition's quota with junk bytes and
  that partition's real puts are refused until the junk is swept.
- **Fetches.** A blob is addressed by its hash. Anyone holding the hash can fetch the bytes from
  the room, whatever their grant. A hash leaks easily (a row a device was once entitled to, a log
  line, a URL), so in a gated room the hash works as a bearer secret: the posture D40 rejected
  for rows.

RFC-0023 §10 already says blob fetches of doc bytes require custody of the partition.

## Options

- **A · Check both in a gated room.** A put whose claimed partition the socket's grant does not
  cover is refused with `blob-refused` code `ungranted`. A fetch is served only when the blob is
  referenced by a row in a partition the socket is entitled to, or the socket put it itself. The
  relay already tracks references for the sweep (`blob-keeper.ts`), so the check reuses them.
- **B · Check puts only.** Closes the quota attack, keeps hash-as-bearer for reads.
- **C · Leave both.** Document that a blob hash is a bearer secret.

## Decision

**A**, decided 2026-11-08 (Jace delegated the call). An open room (`open: true`) keeps today's
behaviour, where a room name is already a bearer secret. Sealed partitions are checked too: the
bytes are ciphertext, but a fetch still costs the operator bandwidth and reveals size and timing.
An unreferenced blob a socket did not put is answered `blob-missing`, the same as an absent one,
so a refusal does not confirm the blob exists.

## Watch out

- A reference is recorded when the row event arrives, which can be after the blob. A fetch that
  races its own row is answered `blob-missing` and retried on the client's existing path.
- A narrowed grant narrows fetches at once; bytes already on a device follow D45.
