## Context

Every write, receive and lookup can fail in an expected way (denied, unknown table, offline). The choice here shapes every signature in the codebase and cannot be changed later.

## Options

- **A · `Result` values everywhere for runtime failures; throws only for definition-time defects** (bad table definition at module load). A library like `better-result` with tagged errors (`_tag`) so a `switch` is exhaustive.
- **B · Throw everywhere, catch at boundaries** — conventional JS; easy to forget a catch; a floating promise loses the error silently.
- **C · Throw at the definition site, convert to values at the call site** (oRPC's `throw` + `safe()`) — ergonomic inside handlers, but two models in one codebase and a floating `safe()` is silent loss.

## What the research points to

A. In a mesh, half of all failures are *expected* (offline, denied, pending) and the type system refusing to let you reach `.value` without checking is worth more than stack traces. Known frictions, so they are not surprises: no `?` operator (multi-step fallible logic is guard blocks); a floating `Result` is silent — add a `no-floating-results` lint before shipping; `.unwrap()` is the lazy path back to throws.
## Watch out

Keep 'pending' out of error unions. A timeout means *still waiting*, not failed; every call site that had it in the union got it wrong.

## Decision

**A — `Result` values for runtime failures, throws only for definition-time defects — using `better-result`, re-exported from `@syncmesh/result`.**

- Every syncmesh package imports `Result`, `TaggedError`, `Panic` and `panic` from `@syncmesh/result`, never from `better-result` directly. One nominal type means the "no floating `Result`" lint has one target and a library swap is one file.
- A runtime failure — bad input, missing row, a link that dropped, a write the policy refuses — is `Result.err(new SomeTaggedError({...}))`. Every error is a `TaggedError` with a literal `_tag`, so `error.match({...})` is exhaustive and adding a member breaks the build at every unhandled site.
- A definition mistake — a table declared twice, a policy naming a column that does not exist, a port used before it is opened — is `panic(...)`. It throws a `Panic` at module load or construction, never on a user's device at runtime.
- `Result.gen` is the composition primitive for multi-step operations; no `try/catch` inside syncmesh code except at a boundary with third-party code, wrapped by `Result.try`.

Why A over C: C is tempting for handler ergonomics, but a floating `safe()` is silent loss and it would put two error models in one codebase. The exhaustive `_tag` match is the feature that pays for A's verbosity.
