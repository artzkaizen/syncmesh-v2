## Context

A phone is a full replica with finite disk; a server wants rows in *its* database. Both need an event log port and a materialised-state port, and the engine's boot reads both. Whether those ports are sync or async decides whether Postgres (async drivers only) and Rivet (async SQLite) are reachable at all.

## Options

- **A · Synchronous ports, synchronous boot** — simplest engine; `bun:sqlite`, `better-sqlite3`, sqlite-wasm all fit; **Postgres and Rivet do not** (found the hard way in the exploration).
- **B · Async ports and an async boot from day one** (`await Engine.open()` or a `ready` promise) — every driver fits; the sync-path cost must be measured so a phone does not pay for the server's convenience.
- **C · Both** — sync core for devices, an async adapter layer for servers. Two code paths to keep honest.

## What the research points to

B, decided now — retrofitting async onto a sync boot was the one wall the exploration hit that it could not climb. Keep the driver port tiny (`run/all/get/transaction?/close?`) and structural so adapters are ~20 lines and never see SQL. One SQLite store, N drivers; the exploration found two near-identical stores had already drifted (one migrated old databases, one did not — and the missing migration corrupts signatures).
**Prior art — automerge-repo.** Its storage port is six methods over a hierarchical key/value store (`load/save/remove/loadRange/removeRange/close?`); all chunking and compaction live in a subsystem above it, and an IndexedDB adapter is ~80 lines. Compaction is size-based: `snapshotSize < 1024 || incrementalSize >= snapshotSize`. A `SavedHeads` sequence counter guards the last-saved marker against a compaction racing an incremental save — a problem that appears the moment saves are async. See `research/prior-art-automerge.md` §3.

## Watch out

Boot invariants: `maxHlc()` and `lastSeq(peer)` must never regress or new events are stamped below ones peers already saw and silently dropped as stale. `appendBatch` in one transaction is ~650× faster than per-event appends on SQLite. Durable by default — memory must be asked for; a default that loses every write on restart is the wrong shape.
