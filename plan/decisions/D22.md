## Context

D13 decided additive-only evolution, and its headline case is a device three weeks offline
meeting events from a build it does not know. E18 built the machinery for that: contiguous
cursors so a hole can be held open, a quarantine that parks rather than drops, `unknownHandling`
to say how loudly, and `retryQuarantined()` for after the update lands.

**None of it can fire for a new change kind**, which is the case it was built for. The codec
refuses the event whole one rung earlier:

```ts
// packages/wire/src/event-codec.ts
if (kind !== KIND.insert && kind !== KIND.update) return malformed("unknown change kind");
```

Both transports then drop a `MalformedEvent` before `admit` ever runs — the bridge reports a wire
error and returns, the relay session skips it. So `unknownHandling` never applies, `onQuarantine`
never fires, and `retryQuarantined()` after the upgrade has nothing to retry. Reproduced in
review with a properly signed v1 envelope carrying `kind: 3`, which is the `increment` the kernel
now understands and the event codec still will not carry.

The codec's own comment argues the refusal, and the argument is good as far as it goes: *folding
an unknown payload as an ordinary value would silently mangle the column.* Refusing beats
mangling. The question this decision answers is whether refusing beats **parking**, and what
parking would even mean for a change whose payload this build cannot read.

It is live rather than hypothetical: E26 has already added `increment`, `add` and `remove` to the
kernel and the wire's `CELL_KIND`, reserved at 3–5. The first release that emits one will be
refused by every peer on the current build — not parked, refused — and E18's whole apparatus will
sit unused while it happens.

## Options

- **A · Widen the kernel's `Change` union with an opaque variant.** `{ kind: "unknown", tag:
  number, table, key, data: CborValue }`. The decoder stops refusing, the event reaches `admit`,
  and the ladder's existing `unfoldable()` rung parks it as `unknown-kind` — the bucket
  `QuarantineReason` already names. The fold refuses to apply it, so nothing is mangled.
- **B · Refuse the event, park the bytes.** Leave `Change` closed and the decoder strict; make the
  transports hand a `MalformedEvent` to the quarantine as raw bytes instead of dropping it. The
  engine never sees a half-understood event, and the quarantine holds something it cannot
  describe beyond "this did not decode".
- **C · Version the event envelope.** A `v: 2` core whose changes are length-prefixed, so an old
  decoder can skip a change it cannot read and fold the rest of the event. Changes the wire
  format and the frozen vectors.

## What the research points to

**A or B**, and the choice turns on where the boundary belongs rather than on effort.

A keeps the parking machinery uniform: one path, one reason, one retry, and the parked thing is a
`StoredEvent` like every other. Its cost is that the kernel's `Change` union stops being closed —
every `switch` over it gains a case, and the type system stops proving that a folded change is one
of three shapes. That is a real loss, and D13's watch-out about upcasters was fundamentally about
not letting unknown data walk further into the system than it must.

B keeps the union closed and the boundary sharp: nothing that failed to decode is ever an
`Event` in memory. Its cost is a second parking path with its own storage shape, its own bound,
and its own retry — and a parked thing with no author, no seq and no partition, because reading
those means decoding the core this build just refused. That last point may be fatal: **the
quarantine is keyed by author and sequence**, and a hole in a contiguous cursor is a hole *at a
sequence*. A parked blob that cannot say where it sits cannot hold a cursor open, which is the
entire purpose. B likely needs the core decodable-but-changes-opaque, at which point it is A with
extra steps.

C is the honest long answer and the wrong one now: it breaks the frozen vectors E03 pins, and it
solves at the envelope a problem that only exists for one field.

The prerequisite either way, already being built: an event must keep the **bytes it arrived
with**, or the parked thing is a partial parse whose signature no longer covers it, and the later
build that is supposed to understand it never gets what it needs.

## Watch out

- Whatever parks must be **bounded and loud on eviction**. An unknown kind arriving in a loop is
  the shape of a denial of service that fills a device's disk with events it will never read.
- A parked unknown must not gate *delivery* of the author's later events, only the **cursor**.
  That distinction was just built for refusals; the same rule applies here.
- Under A, `unfoldable()` must refuse an `unknown` change at the fold **and** at the probe, or a
  device could author one locally.
- Whatever is chosen, it must be true that two peers with the same events park the same set. A
  device that folds what its neighbour parks is the divergence D13 exists to prevent.

## Decision

**A.** The kernel's `Change` union gains an opaque variant — `{ kind: "unknown", tag, table, key,
data }` — the decoder stops refusing on an unrecognised tag, and the event reaches `admit`, where
the ladder's `unfoldable()` rung parks it as `unknown-kind`. One parking path, one reason, one
retry, and the parked thing is a `StoredEvent` like every other.

The union stops being closed, and that is the price. Every `switch` over `Change` gains a case
and the type system no longer proves a change is one of three shapes. What buys it back is that
the alternative does not work: the quarantine is keyed by author and sequence, and a hole in a
contiguous cursor is a hole *at a sequence*, so a parked blob that cannot say where it sits
cannot hold the cursor open — which is the whole reason it is parked. B keeps a boundary that
sounds sharper and cannot do the job.

Four rules the implementation must hold to, all of them a failure this repo has already had:

- **An `unknown` change never folds and never authors.** `unfoldable()` refuses it at the fold
  *and* at the probe. A device that could write one locally would be inventing an event no build
  can read, and the row it touched would then differ from every peer's.
- **It gates the cursor, never delivery.** The distinction was just built for permanent refusals,
  where parking every ladder verdict stopped an author's whole stream for good. The same applies:
  the wire cursor stops below the hole, and later events from that author still arrive.
- **Bounded, and loud when it evicts.** An unknown kind arriving in a loop is how a device's disk
  fills with events it will never read. Silent eviction would drop exactly the thing the device
  was explicitly holding on to.
- **Two peers with the same events park the same set.** No part of this may depend on what a peer
  folded first or on what build it happens to be — a device that folds what its neighbour parks
  is the divergence D13 exists to prevent, and it must be pinned by a test comparing digests
  across two engines rather than one engine against itself.

The prerequisite stands and is being built separately: an event must keep **the bytes it arrived
with**. Without that the parked thing is a partial parse whose signature no longer covers it, and
the later build that is supposed to understand it never receives what it needs.

What this does **not** settle: envelope versioning (option C) stays available for a change that
genuinely cannot be expressed additively. This decision is about a *field* an old build cannot
read, not about a format it cannot parse.
