## Context

SyncMesh does not ship radios; it ships a contract anything can implement. The question is how small the contract is and which real transports come first.

## Options

- **A · Two-tier port** — required `name/start/stop`; optional `onStatus`, `visibility` (only with an ordered log), `blobs` (only with a side channel). A frame link is `send(frame)` + `onFrame(cb)` where `send` **must throw** if the frame did not leave. Most transports extend a base class and write ~20 lines.
- **B · A single fat interface** every transport must fully implement — a BLE radio would have to pretend to have a log position it does not have.

## What the research points to

A. Order: WebSocket relay first (it is what every test runs against), then BLE by porting the old repo's proven handshake/fragmentation with encryption turned **on** and the bare-frame fallback deleted, then Wi-Fi Aware. Route scoring (`pickRoutes`) is pure and tested but is dead code until a second radio exists — do not wire it early.
**Prior art — automerge-repo.** The network adapter port: `connect / send / disconnect / isReady / whenReady` plus events `peer-candidate / peer-disconnected / message`. `whenReady()` is a promise the repo awaits, and the websocket client force-readies itself after 1 s so a dead network never wedges it. One adapter can reach many peers (messages carry `targetId`); ours is one link = one peer — decide which. Every adapter runs a shared acceptance suite (`runNetworkAdapterTests`) — the pattern most worth copying. **Not** to copy: their client logs-and-drops a send on a non-open socket. See `research/prior-art-automerge.md` §2, §4.

## Watch out

Losing a frame loudly is recoverable (cursors re-request it); losing it silently is divergence. Every transport subscribes to `onOutbound`, so with two radios every event goes out twice and inbound dedup makes that a no-op — that is what makes adding a radio safe.

## Decision

**A — the two-tier port; one link = one peer.**

Required `name / start / stop`; optional `onStatus`, `visibility`, `blobs` — an absent capability is a fact about the medium, not a bug. A frame link is `send(frame)` + `onFrame(cb)`, and `send` throws if the frame did not leave (automerge's log-and-drop is the anti-pattern; a loud failure is recoverable by resync, a silent one is divergence). `whenReady()` with a force-ready timeout so a dead network never wedges the mesh.

One link = one peer: many-peer media (a relay room, a Wi-Fi Aware cluster) present as a transport that mints one link per peer it discovers, which keeps the bridge, the gap rule and the tests single-peer simple. `runTransportTests(setup)` is the shipped acceptance suite every transport runs — the automerge pattern most worth copying. Order of radios stands: WebSocket relay (E12), then BLE with encryption on, then Wi-Fi Aware; `pickRoutes` stays pure and unwired until a second radio exists.
