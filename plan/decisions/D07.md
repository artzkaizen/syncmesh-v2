## Context

Full replication of everything to everyone caps scale and makes the log unbounded. Data has to be scoped, and the scope has to be enforced at the wire, not just hidden at read time.

## Options

- **A · App-declared partition kinds with a hierarchy** (`org` → `site`), events stamped `kind:id` inside the signed payload, grants listing instance ids, top-level kinds optionally `isolation: "database"` (own engine, own store — leaving an org deletes one file). Reserved `user` (account-private) and `local` (device-only, refused on the wire). Ambient scope via generated setters (`setOrg`, `setSite`) so a cross-tenant write is inexpressible.
- **B · One flat `group` tag per row, one store** — simpler, cross-group queries work locally, but a device holds every group it has ever seen in one log.
- **C · LiveStore's one-store-per-scope** with no nesting and no cross-scope queries.

## What the research points to

A — it is what the exploration built and tested, and the ambient setters are the feature: there is no `{ site }` argument on any call, so a silent cross-site write cannot be written. Watch the two axes: *partition* (what the event belongs to) versus *storage scope* (which file it lives in) are related but not the same.
## Watch out

Grants list bare instance ids (`["acme"]`) while events carry `"org:acme"` — that asymmetry cost a debugging cycle. Decide one form. One event = one partition: a transaction spanning two is refused, not split.

## Decision

**A — app-declared partition kinds, with the refinements the use cases forced (`plan/use-cases.md`).**

- Kinds are a tree in the manifest (`{ org: { shelf: {} } }`); a top-level kind gets its own store per instance, a nested kind lives in its parent's. There is no `isolation` flag and no `parent` string: position is the whole declaration.
- Instances are `kind:id` strings **everywhere** — on events and in grants alike. The exploration lost a debugging cycle to `["acme"]` in grants versus `"org:acme"` on events; one form ends that.
- Reserved kinds: `user` (the account's devices), `local` (this device, never on the wire), and `global` (server-written, replicated to every device, device-read-only). A table with no `partition` is global.
- The active instance is ambient: `mesh.activate("org:acme")`, set once by the org switcher; no call takes a partition argument, so a cross-tenant write cannot be written. Instances come from the grant, never from `createMesh` configuration.
- Rows that no partition can hold — shared across tenants, or visible by a state or time predicate — are `visibility: "authority"`: the relay decides admission from the app's data (RFC-0020). A partition is the unit of replication; an entity tree or a status is a visibility filter inside one, not a partition.
