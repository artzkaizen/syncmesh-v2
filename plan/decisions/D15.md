## Context

A device cannot rebuild from its own log after compaction — the tail is gone by design. So the floor must never pass what a peer still needs, and someone has to supply the floor.

## Options

- **A · Caller-supplied cursor maps; floor = per-author minimum across them; clamped to the persisted snapshot** (what exists).
- **B · Automatic ack floors from the cursor exchanges peers already do, plus `keepAtLeastDays`.**
- **C · B plus a policy for dead peers** — a device that never returns pins the floor forever; evicting it from the known-peer set has data-loss teeth.

## What the research points to

B, and write the C policy into the RFC before implementing it — it is the open question with teeth. Boot = snapshot + tail, never a full-log refold; compaction never passes the persisted snapshot's coverage.
## Watch out

`history()` and any audit read are bounded by the log; do not promise more than compaction leaves.

## Decision

**B — automatic ack floors, plus `keepAtLeast`; C's dead-peer policy written into RFC-0015 §2a and built as `forgetPeersAfter`.**

The floor is derived, never supplied: a link records what the far side holds on every cursor exchange (`engine.acknowledge(peer, cursors, at)`), `engine.compact({ now, keepAtLeast?, forgetPeersAfter? })` takes the per-author minimum across the peers still counted, and clamps it to what the state store has persisted — a device cannot refold what it deleted, so without a state store compaction is refused as a value (`CompactionRefused`), not silently a no-op. Local-scope events need no peer and compact to the persisted local coverage. Acks live in memory: after a restart nothing compacts until peers talk again, which is the conservative side.

Dead peers: a peer silent longer than `forgetPeersAfter` stops pinning the floor. If it returns below the floor it cannot delta-sync and rejoins from state (RFC-0015 §3, E14); that is the data-loss tooth, chosen over a floor frozen forever by a phone in a drawer. The event store persists the floor it compacted below (`compactedBelow`), so a state cache that turns out corrupt over a compacted log fails boot with `StateCorrupt` — "rejoin from a peer" — instead of rebuilding a partial state from half a log.

Automerge's `SavedHeads` guard is not needed here: coverage is monotone and commits in the same transaction as the rows it covers, so a compaction computed from an older coverage only ever deletes below what is persisted. `snapshotEvery` is subsumed — the state store is always current, boot is open + tail (D05). A size-based trigger stays open: the engine exposes `compact()`; when to call it belongs to the client (E09).
