## Context

`Transport` carried its blob side channel as two flat optional members, `putBlob` and
`fetchBlob`, and the relay attached them by pointing each at a method of its internal channel:
`putBlob: link.blobs.put, fetchBlob: link.blobs.fetch`. Two things were wrong with that, and
neither was the verbs.

The port already had the other shape. `visibility?: TransportVisibility` is one optional member
holding `token` and `visibleAt` — a capability is a *thing a medium has*, and it is declared, tested
for, and wrapped as one thing. `research/API.md` §9 specified blobs the same way,
`readonly blobs?: BlobCapability // only with a side channel`, and the implementation flattened it.
The cost showed up in every reader: `withBlobs()` tested `putBlob !== undefined` and hoped
`fetchBlob` agreed; the telemetry wrapper had two `if` blocks where the visibility capability
needs one; a fake in a test declared one and not the other and was still a `Transport`.

To decide the verbs rather than inherit them, the reference was `files-sdk` (`files-sdk.dev`,
v2.6.0), a unified storage SDK over forty-odd backends. Its **adapter** contract — the seam a
backend implements, the analogue of what a transport implements here — is a plain object of
function-valued properties with required and optional members and advisory `supportsX` flags: the
same two-tier port as D12-A, and a plain object rather than a class for the reason D29 gives.
Its verbs at that tier are `upload` and `download`; `head`, `exists`, `delete`, `list` beside
them; a missing key is a `FilesError` with a `NotFound` code, and `exists` folds that one code to
`false` and rethrows the rest. Vercel Blob and R2 use `put`/`get` at the same tier; the Claude
Files API uses `upload`/`download` with `retrieveMetadata` between them.

## Options

- **A · Leave it flat.** `putBlob` / `fetchBlob`. Rejected: it is the one capability on the port
  declared as two members, and every reader has to check both agree.
- **B · Nest, keep the app tier's verbs.** `blobs.put` / `blobs.fetch`, matching `mesh.blobs`.
  One vocabulary across two tiers reads as tidy and is the wrong kind of tidy: `mesh.blobs.put`
  stores locally *and* offers to every carrier, while the transport's member only offers to one.
  The same name for a different promise.
- **C · Nest, in the verbs of a transfer.** `blobs.upload` / `blobs.download`. What the relay
  literally does, what the reference SDK's adapter tier calls it, and a name that cannot be
  mistaken for the store's `put`/`get` beside it.

## Decision

**C.** `readonly blobs?: TransportBlobs`, with

```ts
interface TransportBlobs {
  readonly upload: (hash: string, bytes: Uint8Array) => Promise<void>;
  readonly download: (hash: string, options: DownloadBlobOptions) => Promise<Uint8Array | undefined>;
}
```

1. **Three tiers, three vocabularies, because they name three different things.** The store
   (`BlobStore.put/putAt/get/has/delete`) is bytes at rest on this device. The transport
   (`blobs.upload/download`) is bytes crossing one medium. The app surface (`mesh.blobs.put/fetch`)
   is the resource — a put that lands locally and fans out, a fetch that checks the cache first.
   A reader seeing `download` knows a network is involved and a deadline applies; seeing `get`
   knows neither is. Collapsing them would have made the verb say less.

2. **The deadline moved into an options object**, `{ timeoutMs }`, rather than staying
   positional. `mesh.blobs.fetch` already takes `FetchBlobOptions` with `timeoutMs` and
   `onProgress`; the reference SDK's `download` takes `{ range, signal, timeout, onProgress }`.
   When chunked frames land (book ch. 12), `onProgress` has a place to go without breaking the
   seam a second time. Nothing else is in the bag today, deliberately.

3. **The relay hands the seam a typed object, not two picked members.** `createBlobChannel`
   returns `{ capability: TransportBlobs, answer }`; the literal says `blobs: link.blobChannel.capability`.
   If `TransportBlobs` grows, the channel is the one place that has to answer for it — the same
   objection D17 and D29 make to a wrapper that lists the members it knows.

## What this costs, accepted

- **A breaking change to the port**, for every transport that declared the capability. In this
  tree that is one: the relay. A third-party transport declaring `putBlob` now declares nothing,
  and `mesh.blobs` answers `NoSuchCapability` — loud, not silent.
- **`spreadable` checks the top level only.** `blobs` is a literal in every producer here, and a
  class instance nested under it would pass the shape case. The guard is for the seam; the rule
  is D29's, and it applies one level down as well.

## What this does not settle

- **`mesh.blobs`' own verbs.** `put` / `fetch` stay. They are the app-facing REST-shaped surface,
  documented in API.md §22, and this record is about the port beneath them.
- **The telemetry event names** `mesh.blob.put` / `mesh.blob.fetch`, emitted from the transport
  wrapper but named for the mesh-level operation they measure. Devtools reads them.
- **`exists` / `head` on the port.** The reference SDK has both; nothing here asks either question
  of a medium yet. Add them with the first caller.
