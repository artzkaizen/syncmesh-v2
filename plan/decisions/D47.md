## Context

`plan/api-gaps.md` §3.1: `createMesh` (`@syncmesh/client`) and `createClient` (`@syncmesh/orpc`)
both exist with callers, and "the book's cut list says one. Mechanical but wide; needs a
sequencing call." The shape is not the open question. It was agreed:

- **The book's cut list** (`research/syncmesh-book.md`, "The cut list, complete"):
  "`createMesh`+`createApp` → `createClient`". Its export table lists `createClient` for
  `@syncmesh/client` and `createServer` for `@syncmesh/server`, and nothing named `createMesh`.
- **The React session, decided** (`plan/react-api.md`, 2026-09-21T16:23:36Z and 18:12:24Z): the
  client is a value, `createClient({ schema, procedures })` returns synchronously, and the app
  pattern is `syncmeshReact(createClient(…))`.
- **The build log** (`research/build-log.md`, "One noun — `createClient` DONE").
- **The code says it is waiting.** `packages/orpc/src/options.ts` documents `flatten` as "the
  grouped options, as the flat bag `createMesh` still takes underneath … When `createMesh` goes,
  this function is what disappears — not every call site."

What the code looks like on main at `d01bb92`:

- **Apps already use the agreed door.** `apps/issues` (`app/host.ts`, `server/lan.ts`) calls
  `createClient` and hands `app.$mesh` to `serveMesh`. `createServer` is built on `createClient`
  (`orpc/src/server.ts` reads `client.$mesh`). No app under `apps/` calls `createMesh`.
- **`createMesh` is still the root export of `@syncmesh/client`** (`client/src/index.ts`), and
  its non-test callers are the layer under the app: `orpc/src/client.ts` (which wraps it),
  `chaos/src/world.ts`, `bench/src/browser-mesh.ts`, `tooling/verify-node-consumer`, and the
  embedded example (`examples/src/embedded/device.ts`, `backend.ts`), plus doc comments in
  `adapters/browser/src/host.ts`, `orpc/src/api.ts` and `client/src/surface.ts`. 44 test files
  call it.
- **E09 still names it.** `plan/epics/E09.md` describes the client epic as `createMesh` →
  `mesh.on(…)`, written before the cut list.

## Options

- **A · Delete `createMesh`.** `createClient` opens the engine itself and nothing else can. Every
  harness (chaos, bench, 44 test files) moves to `createClient`, which requires a `procedures`
  router, so each grows an empty one to reach the mesh it actually tests. Wide, and it makes the
  engine-level tests depend on `@syncmesh/orpc`, the package above them.
- **B · `createClient` is the one public constructor; `createMesh` moves off the root export to
  a subpath for the layers under the app.** `@syncmesh/client` keeps opening meshes, under a
  name an app does not import: `@syncmesh/client/internal`, the spelling `@syncmesh/orpc`
  already uses for its own (`packages/orpc/package.json`), documented as adapter and harness
  surface. The
  grouped options (`storage`, `trust`, `admission`, `entropy`) move down into it, so `flatten`
  disappears as `options.ts` promised. Examples and docs move to `createClient`. Tests and
  harnesses change one import line.
- **C · Keep both public, document `createClient` as preferred.** Two doors, which is what the
  cut list was written to end. Rejected: it reopens a shape Jace agreed.

## Decision

**B**, decided 2026-11-08 (Jace delegated the call). The agreed shape stands: one constructor, and
it is `createClient` (and `createServer`, built on it, for the server). This decision only settles
the sequencing §3.1 asked for. A is rejected because it makes the engine's own tests depend on the
procedure layer to reach the mesh they test, and "one constructor" is a promise about what an app
imports, not about what a test harness may reach.

## What building it involves

In this order, each step leaving `vp check` and the full test run green:

1. **Docs and examples first.** `examples/src/embedded/device.ts` and `backend.ts` move to
   `createClient` / `createServer`; the doc-comment examples in `adapters/browser/src/host.ts`,
   `orpc/src/api.ts` and `client/src/surface.ts` show `createClient(…).$mesh` (as
   `apps/issues/src/app/host.ts` already does); E09's opening line names `createClient`.
2. **The subpath.** Add the internal entry to `@syncmesh/client`'s `exports`, move `createMesh`
   there, drop it from the root. `orpc/src/client.ts`, `chaos`, `bench`,
   `tooling/verify-node-consumer` and the 44 test files change their import.
3. **Grouped options down.** `createMesh` takes the grouped `ClientOptions` shape (minus
   `procedures`, `link`, `windows`), and `flatten` is deleted.
4. **A guard.** A test that `@syncmesh/client`'s root export has no `createMesh`, failing before
   step 2.

## Watch out

- **`$mesh` is the escape hatch, and it stays.** `serveMesh(app.$mesh)` and `createMeshSource`
  take a `Mesh`; that type stays public. Only the constructor moves.
- **Other branches touch the same call sites.** The examples directory is being reorganised in
  the owner's working tree (`examples/` into `apps/hosting` and `apps/rounds-web`). Step 1 lands
  after that, against whatever paths main has then.
- **A subpath is still importable.** B makes `createMesh` hard to reach by accident, not
  impossible. That is the intent: a harness may, an app should not, and the doc comment says so.
- **`createClient` requires `procedures`.** A device with no procedures (the embedded example's
  phone) passes an empty router. If that reads badly in the example, making `procedures` optional
  is a separate, small API change and needs Jace's yes; this decision does not make it.
