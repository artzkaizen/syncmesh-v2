## Goal

Live queries maintained incrementally from the fold batch's exact touched keys, a ref-counted registry so identical questions share one subscription, and React hooks that take a descriptor (no deps) or a builder (deps required).

## Decisions needed

D11

> **Reshaped by D20 (2026-08-26).** The maintained `LiveQuery`/`QueryRegistry` and query
> descriptors were retired with the collection surface: a live query is now the drizzle
> handle's `live(query)` — re-run on the fold batches that touch its tables, structural
> cutoff, one notification per batch — which is what RFC-0009 itself argued for ("no db-ivm;
> re-running the query is microseconds"). The React layer rides that. The Hermes
> `fn.toString()` trap is gone by construction: a Drizzle query is data, `toSQL()` is its
> identity, so there is no deps array anywhere.

## Tasks

- [x] ~~`LiveQuery` maintained by touched keys~~ → `live(query)` on the handle (D20 §4): re-run on exact table invalidation, after the state-store commit, notify once per batch and only on change
- [x] ~~`QueryRegistry`~~ → sharing is the query's own `toSQL()` key in the hook layer; `release` on unmount
- [x] ~~Query builder~~ → Drizzle is the builder; nothing of ours to build
- [x] `useLiveQuery(handle, query)` — the query built inline every render, keyed by `toSQL()`: same question, same subscription; changed filter, fresh one. `{ rows, ready }`
- [x] `useLiveInfiniteQuery(handle, { page, cursorOf, pageSize })` — keyset windows only, every loaded window stays live, `exhausted` is the short page
- [x] `useCan(mesh, "books.update", row?)` — `useSyncExternalStore` over `grants.onRegistered`; the row comes from a live query, which re-renders on its own changes
- [x] One render per fold batch, load-tested: 200 open `useLiveQuery` hooks, a 5,000-event catch-up in one `receiveBatch`, exactly one extra render each (`packages/react`, the done-when as a test)
- [x] ~~`useLiveQueryEffect`~~ — struck, not built: a component that renders the rows already has them for a plain `useEffect`, and a side effect nothing renders is an app concern that belongs on `handle.live(query).subscribe(...)`, not inside a null-rendering component. Exploration inventory, not demand
- [ ] `usePresence` (RFC-0009 §presence) — blocked on the presence surface itself (RFC-0020 §6)

## Watch out

- The safety invariant: a maintained result must equal what a full re-run would produce, always. Property-test it against a re-run oracle; it will find your off-by-one.
- Hermes returns `"[native code]"` for `fn.toString()` — the builder form needs a mandatory deps array; the descriptor form does not.
- Offset pagination is unstable under live edits. Keyset only.
