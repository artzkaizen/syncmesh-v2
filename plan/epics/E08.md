## Goal

Data belongs to an instance of an app-declared kind; the stamp rides inside the signed payload; a device holds only what its grants cover; top-level instances can be their own engine over their own store; scope is ambient via generated setters so a cross-tenant write cannot be written.

## Decisions needed

D07, D24 (decided: A)

## Tasks

- [x] `partition: "kind:id"` on the event core (key 6, optional); author stamps `_partition` inside the row; receiver verifies row-stamp ≡ event-stamp — done as `RowRecord.partition`, set at fold time from the signed core: no magic column, nothing to strip, one source of truth
- [x] Validator rules: kind matches the table's declared kind; `user` is account-private vs `grant.account`; `PartitionNotGranted`; `local` refused on the wire; one event = one partition
- [x] Generated setters from partition kinds; `NoActivePartition` names the setter — one setter, `mesh.activate("kind:id")` (D07); the error names it
- [x] `publicRow()` strips `_partition` at every app-facing read — nothing to strip: the partition lives on the record, never in the row
- [x] `engine.rowsIn(table, partition)`
- [x] `global` kind: replicated to every device, device-read-only (`Err(ReadOnlyPartition)` on insert), written through the authority (E16) — already in the validator since E16; this batch confirmed it and left it alone
- [x] `visibility: "authority"` tables — built as **admission**, per D24-A. The authority is the only author (the validator's authorship rung, unchanged); the relay is the only gate. `RelayAdmission { tables, entitle }` on `openRelayRoom` and `startRelay` (`packages/relay/src/admission.ts`): the authority's `Entitlement { scope, admits }` is asked once per join, on the room's queue ahead of the scan, and filters catch-up **and** every live fan-out — the fan-out from another instance included, since both reach a socket through the same `offer`. What the six rejected problems became:

  - **1, 2, 6 — gone by construction.** No local verdict exists: a device's write to a gated table is `ReadOnlyPartition` on every peer, a forged one signed by a device that believes itself the authority is refused by every receiver it reaches, and `can()` answers no for a write because the table has no rules to evaluate.
  - **3 — fixed at the root (D24).** `matchesInterest` and `rowsIn` treat an unpinned event or row as belonging to every interest, so `global` and gated rows reach the devices that narrowed.
  - **4 — the withheld event no longer stalls the author's stream**, without a sequence of its own (D24 found it unneeded). Catch-up already ends with D23's scoped coverage; the live path now does the same thing per event: a socket withheld something of an author's is sent an empty last page whose coverage claims that author's run up to the room's contiguous reach, scoped to the interest **and the entitlement** (`scopeText`). A device whose entitlement's name has changed since its cursors were earned re-pages from nothing rather than adopting; `room.reentitle(peers)` is how the authority says its database changed.
  - **5 — `startRelay` reaches the gate** through `hostTuning`, and fan-in cannot walk around it.
  - Peer to peer, a gated row does not travel at all (`Withheld`, filled by `createMesh` from the manifest): no event over a direct link, no rows in a served snapshot and no claim over the authority's run there, and gated tables out of the digest comparison. The cost is stated in `plan/use-cases.md` §4: over a radio alone, the authority's later events wait behind a gated one until the device next reaches the relay.

  Tests: `relay/authority-visibility.test` (same entitlement → same set, live and catch-up; the stalled-stream case; an entitlement that changes; fan-out; a forged write refused everywhere; `startRelay` plumbing), `transport/withheld.test`, `client/visibility.test`, and the two new page vectors in `conformance/relay-vectors.json`.

- [x] ~~`storeFor(scope)`~~ shipped as `scopedStores` in `packages/storage`, and now wired: `createMesh({ stores })` boots over stores someone else opened, so a device runs **one mesh per top-level instance over one database each** (D07). Leaving an org is closing that mesh, `forget(scope)`, and deleting one file — nothing of any other org can be in it, because there is no connection that holds both. Borrowed stores stay the caller's: `stop()` leaves them open, since the set that opened them is what knows when they are done with.

  Wired rather than dropped, and the reason is the one D07 gave: a single mesh filtering one shared log could only ever *approximate* tenancy, and a filter bug there is a tenancy bug.

## Watch out

- `_partition` leaked into every row the app read in the exploration — the row type lied and a spread-then-write carried a stale stamp. Strip at the boundary, once.
- Leaving an org must delete one store and nothing else.

## Tests

- `partitions.test`, `storage-isolation.test` (logs never mix; drop one store), the partition cases in `syncmesh.test`.

## Done when

A cross-partition tx is refused before commit; `_partition` never appears in an app-facing row; dropping one org's store leaves every other intact.
