## Goal

Data belongs to an instance of an app-declared kind; the stamp rides inside the signed payload; a device holds only what its grants cover; top-level instances can be their own engine over their own store; scope is ambient via generated setters so a cross-tenant write cannot be written.

## Tasks

- [x] `partition: "kind:id"` on the event core (key 6, optional); author stamps `_partition` inside the row; receiver verifies row-stamp ≡ event-stamp — done as `RowRecord.partition`, set at fold time from the signed core: no magic column, nothing to strip, one source of truth
- [x] Validator rules: kind matches the table's declared kind; `user` is account-private vs `grant.account`; `PartitionNotGranted`; `local` refused on the wire; one event = one partition
- [x] Generated setters from partition kinds; `NoActivePartition` names the setter — one setter, `mesh.activate("kind:id")` (D07); the error names it
- [x] `publicRow()` strips `_partition` at every app-facing read — nothing to strip: the partition lives on the record, never in the row
- [x] `engine.rowsIn(table, partition)`
- [x] `global` kind: replicated to every device, device-read-only (`Err(ReadOnlyPartition)` on insert), written through the authority (E16) — already in the validator since E16; this batch confirmed it and left it alone
- [ ] `visibility: "authority"` tables — **attempted and rejected (2026-08-28); the attempt is preserved in the session scratchpad.** Six confirmed problems, and they are one problem wearing six hats: the tier was built as *validation* when it is *admission*. Whoever picks this up should start from that.

  - **A verdict that depends on a local flag.** Giving the tier an `allow` block turned `checkPolicy`'s dormant `isAuthority` skip into the live path, so a device folds and keeps a write the authority quarantines — with no correction path, because the authority never accepted the event. The test blessed the split rather than catching it.
  - **`can()` and `validate()` disagree** on the same device for a gated table, contradicting `can`'s own guarantee.
  - **The tier's rows are undeliverable to any narrowing device.** The rung guarantees `event.partition === undefined`, and an unpinned row matches no interest that names partitions — so `global`, whose whole point is "replicated to every device", reaches everyone except the devices it exists for. Fixing it means teaching `matchesInterest` / `rowsIn` that an unpinned row belongs to every interest, which needs a convergence argument of its own.
  - **A withheld event stalls that author's whole stream**, because holdback releases only a contiguous run and nothing ever fills the gap. The gated tier needs a sequence of its own.
  - **`startRelay` cannot gate anything** — the option never reaches a room, so the feature was reachable only by calling `openRelayRoom` directly, and fanout ingress bypassed the gate entirely.
  - **A synced `_policy` doc can never govern the tier**, since the doc is keyed by a partition the tier's events are now guaranteed not to carry.

- [ ] ~~`storeFor(scope)`~~ shipped as `scopedStores` in `packages/storage` and **has no consumer**: the mesh still opens one store for everything, so D07's "leaving an org deletes one file and nothing else" is not reachable from the app surface. Wire it or drop it: the relay evaluates admission against app data and devices receive a subset; never obtainable peer-to-peer without the authority having admitted the receiver (`plan/use-cases.md` §4)

## Watch out

- `_partition` leaked into every row the app read in the exploration — the row type lied and a spread-then-write carried a stale stamp. Strip at the boundary, once.
- Leaving an org must delete one store and nothing else.

## Tests

## Done when

A cross-partition tx is refused before commit; `_partition` never appears in an app-facing row; dropping one org's store leaves every other intact.
