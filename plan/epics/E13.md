## Goal

An operator dataflow that turns 'what is the answer now?' into 'what changed about the answer?' — used by the relay to serve row patches to many subscribers without recomputing each one per event, and by interest filtering on the wire.

## Decisions needed

D11

## Tasks

- [ ] `Pred` (`eq ne lt lte gt gte isIn and or not always`) as data; `evalPred`; stable `predKey`
- [ ] Operator pipeline `Source → Filter → Take → view`; `ivmQuery(engine, opts)` maintained from fold batches
- [ ] `ClientView` — one per socket; refcounted rows shared across queries, evicted at zero; patches **queued** through backpressure
- [ ] `Interest { partitions?, tables?, since?, where? }`; `matchesInterest`; `engine.eventsSince(cursors, interest)` filtering at the **sender**
- [ ] Relay frames `desire / undesire / rows`

## Watch out

- A relay serving queries holds materialised state — a departure from 'the relay executes nothing'. It still cannot forge, but it is a second product lane; name it as one.
- Patches carry no epoch or monotone id yet, so a reconnect can only clear and re-desire — versioned patches are E24.

## Tests

- `ivm-engine.test`, `ivm-pipeline.test`, `cvr.test`, `relay-cvr.test` (100 disjoint queries over 16 KB rows, ~32 MB in one burst, must not stall), `interest.test`.

## Done when

The relay serves 100 disjoint queries without stalling; a maintained view equals a re-run.
