## Goal

Sync an existing database into the mesh: the database stays authoritative, devices get a signed read-only projection, writes travel back the other way. One direction per table, never both.

## Decisions needed

D10

## Tasks

- [x] `ChangeSource` port: `start({ after }) → { changes: AsyncIterable, ack(watermark), stop }`; messages `begin / insert / update / delete / truncate / commit(watermark)`
- [x] `manualChangeSource()` first (your app calls it), then Postgres logical replication
- [x] Transaction → one signed event per partition touched; ack only after the event is durable; the watermark in a reserved `_cdc` table on **its own unpinned event, last** — not the same commit, which is where the task originally pointed. A reserved row's partition is set at fold from the event's, first-seen-wins and hashed into its digest, so riding whichever instance a transaction touched last made the row's partition a function of fold order: two peers with the same events disagreeing forever, unhealable by repair. A separate last event keeps the durability argument exactly — the position still lands strictly after every change it covers — and `UNPINNED_RESERVED` in the validator makes the pinned form impossible rather than merely absent
- [x] Backfill via a table read at a captured watermark; schema changes in the stream are an **alarm**, not an instruction; `truncate` capped

## Watch out

- Ack early and a crash loses the change with no way to re-request it — the same bug class as a transport that resolves `send` on a dropped frame.
- Ownership policy on CDC tables must read the column (`rowIs`), never the author — the authority signs everything.

## Tests

- A three-row transaction becomes exactly one event per partition; crash between event-commit and ack replays without divergence; a device write to a CDC table is denied locally and quarantined remotely.

## Done when

An existing Postgres table appears on phones, offline, read-only, without being defined twice.
