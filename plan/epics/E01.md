## Goal

A pure, I/O-free core that converges: a hybrid logical clock, stamps with a total order, a row record with per-cell stamps and tombstones, and a merge that is a lattice join. If two peers fold the same changes in any order and hold the same row, the system converges; nothing above this can fix it if not.

## Decisions needed

D04 conflict model

## Tasks

- [x] `Hlc = [physicalMs, logical]`; `HlcClock.tick()` and `.receive(remote)` that ratchet forward under a backward wall clock
- [x] `Stamp = { hlc, peer }` and `compareStamp` — a total order, ties broken by peer id
- [x] `RowRecord { cells, writeStamp, deleteStamp }` (each cell carries its stamp); `isVisible` (write beats delete)
- [x] `applyChange(state, change, stamp, merge?)` — field-level LWW; per-column strategy `lastWrite | max | min` where `max`/`min` compare values and the stamp breaks exact ties. Strategies are a table keyed by name, not a `switch`: E26 adds `counter`, `set`, `text` without touching this function
- [x] `mergeRecord(state, table, key, record, merge?)` — whole-record merge by stamps, for snapshots
- [x] Decide and document insert × insert (field-merge vs whole-row) — **field-merge**: a concurrent insert merges column by column exactly like an update, so every strategy stays a join and no column is lost; tested in `apply.test.ts`
- [x] Property tests: commutativity, associativity, idempotence under random order + duplication; HLC monotonicity under backward clocks; `max` converges to the maximum under any interleaving

## Watch out

- `compareStamp` off by one `<=` silently breaks dedup and LWW under equal HLCs. Test equal stamps explicitly.
- All three strategies must be lattice joins; if you add one that is not, convergence is gone and nothing will tell you.
- Deletes are stamps, not removals. A row deleted then re-inserted with a newer stamp is visible; with an older one it stays deleted.

## Tests

- `hlc.test` — tick/receive; monotonic under `now()` going backwards; clamp on absurd remote clocks.
- `kernel.test` — every cell of the collision matrix, in both delivery orders.
- `properties.test` (fast-check) — thousands of random schedules; three-engine convergence once E02 exists.
- `merge-strategies.test` — the bid/ask examples; a property over random interleavings.

## Done when

The property tests pass at thousands of schedules and the collision matrix has a test for every cell.
