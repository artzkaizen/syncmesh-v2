## Goal

Ship state, not history: a joining device receives the rows it is entitled to and can show, adopts cursors only when the snapshot is complete, and gets one signature per chunk instead of per event over a slow radio. Then put it on the wire.

> epic needs — `Interest` and sender-side filtering — with the IVM it used to carry retired and
> the relay's row path moved to E27. The dependency stands, and is now a smaller one.

## Tasks

- [ ] `snapshot()` / `installSnapshot()`; `snapshotFor({ interest, window })`; `installScopedSnapshot()` merging by stamp, one fold batch; tombstones included
- [ ] Compact snapshot codec (dictionaries + stamp dedup)
- [ ] Per-author feed chains (`advanceFeed`, sha256) → `chunkSince` / `receiveChunk` with one signature per run
- [ ] Wire: `snap-req → snap-manifest → snap-chunk* → snap-ack`, paged through the relay's backpressure; adopt cursors only after every chunk verifies; mark a provisional (unsigned) join in state
- [ ] `join` carries an interest; relay filters catch-up and live fan-out by it
- [ ] `bench/join` — the four strategies, reproduced over the wire

- [ ] Source priority for a join: local storage answers before the relay may say 'nothing to catch up', and the relay before a radio — do not declare a scope empty until the higher-priority source has finished

## Watch out

- A snapshot must be COMPLETE for its scope or the missing rows are missing forever — adopting cursors is the saving and the risk.
- A backfill must never resurrect a tombstoned row.
