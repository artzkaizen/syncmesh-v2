## Goal

A contract anything can implement: required `name / start / stop`, optional `onStatus / visibility / blobs`. A frame link is `send(frame)` + `onFrame(cb)`. The bridge carries signed events, grants (first) and cursor catch-up identically across every radio.

Test: drop one middle frame on the loopback, assert convergence after resync
- [x] Outbound priority classes at the bridge — the `KIND` tag is the class, so routing and outbound can never drift. Only the first half of the epic's wording: catch-up events still carry `KIND.event` exactly like live ones, so **live-before-bulk is not implemented** and wants a class of its own, specced now, observable in E12: `grant`/`cursors` before `event`, live events before catch-up bulk; the frame type is the class tag (RFC-0012's interactive vs bulk)
- [x] `grant-request` frame `{ peerId, invite? }` (decided, D08 addendum) — an ungranted peer sends its peerId plus an optional invite token; the far side forwards to the issuer route, or surfaces it for approval where `issuerKey` is held (`mesh.grants.issue`), and answers with a grant frame. Nothing in the frame is trusted; the carrier is a courier by construction (`plan/flows/grant-onboarding.md`)

- [x] **Every transport runs the shared contract, not just the loopback.** `transportTests` was written for exactly this and only the loopback ever ran it — `@syncmesh/transport/transport-tests` was declared in `exports` but never added to the build entries, so no other package could import it. BLE runs it now over a virtual air where three real `bleTransport`s hear each other (advertisements reach scanners, a dial reaches the advertiser, a write lands as a write request, a notification returns to its subscriber), and the relay runs it through a real room with a socket that reports a frame as sent and then drops it, which is what the gap rule has to survive.

  Two cases added while wiring them, both about the shape a pair cannot show: concurrent writes from all three peers while apart, and a peer with nothing of its own to say still carrying its neighbours' writes on the fourth round.

## Watch out

- Losing a frame loudly is recoverable — cursors re-request it. Losing it silently is divergence until something forces a resync.
- An absent optional capability is a fact about the medium, not a bug. A BLE radio has no log position to report.

- automerge's websocket client logs-and-drops a `send` on a non-open socket. Their protocol survives it (Bloom resync + in-flight re-send); ours must not copy it — `send` throws, cursors re-request.
