## Goal

A contract anything can implement: required `name / start / stop`, optional `onStatus / visibility / blobs`. A frame link is `send(frame)` + `onFrame(cb)`. The bridge carries signed events, grants (first) and cursor catch-up identically across every radio.

- [ ] **Gap rule** — cursors are max-based, so a dropped middle frame would be jumped and silently lost: the bridge folds an author's events only contiguously (per-author holdback for out-of-order arrivals) and `resync()` re-requests from the last contiguous seq. Test: drop one middle frame on the loopback, assert convergence after resync
- [ ] Outbound priority classes at the bridge, specced now, observable in E12: `grant`/`cursors` before `event`, live events before catch-up bulk; the frame type is the class tag (RFC-0012's interactive vs bulk)
- [ ] `grant-request` frame `{ peerId, invite? }` (decided, D08 addendum) — an ungranted peer sends its peerId plus an optional invite token; the far side forwards to the issuer route, or surfaces it for approval where `issuerKey` is held (`mesh.grants.issue`), and answers with a grant frame. Nothing in the frame is trusted; the carrier is a courier by construction (`plan/flows/grant-onboarding.md`)

## Watch out

- Losing a frame loudly is recoverable — cursors re-request it. Losing it silently is divergence until something forces a resync.
- An absent optional capability is a fact about the medium, not a bug. A BLE radio has no log position to report.

- automerge's websocket client logs-and-drops a `send` on a non-open socket. Their protocol survives it (Bloom resync + in-flight re-send); ours must not copy it — `send` throws, cursors re-request.
