## Goal

Store-and-forward of signed bytes by a process that holds no keys: rooms, per-author cursors, paged catch-up with grants first, durability acks with log offsets, backpressure that never drops and never grows, a durable room log, and a host-agnostic core that runs under Bun, a Durable Object, or an actor.

## Decisions needed

D09 topology · D14 handshake versioning

## Tasks

- [x] `openRelayRoom({ name, store, epoch, keepaliveMs?, pageSize?, maxBacklog?, fanout? })` over an `EventStore` and a `RelaySocket { send, close }` whose `send` answers honestly (`sent | buffered | dropped`)
- [x] `join` → `hello { v, keepalive, epoch }` + paged catch-up (2,000/frame, grants in page one, `more`, offset `o`) + the relay's own cursors
- [x] `ka` keepalive on cadence; `epoch` persisted with the log (in `_relay_meta`, same SQLite file)
- [x] `ingest`: verify + dedup by event id (= peer-seq), append, `ack { id, o }` to the author, relayed `{ w, o }` to everyone else
- [x] Grants store-and-forward by bytes (byte-identical, first page of every catch-up)
- [ ] `blob-put` verify-on-put / `blob-get` / `blob-missing` (with E13)
- [x] `createSender` + `drain` — `ws.send()` returning 0 means *not sent*; per-socket backlog in order; at the ceiling, **close**
- [x] `startRelay(port, { store?, dataDir?, fanout?, keepaliveMs?, pageSize? })` — durable by default under `.syncmesh/relay/`, one SQLite log per room, rooms named by URL path
- [x] `Fanout` port (self-excluding links); `memoryFanout()`; best-effort, cursors recover what it misses
- [ ] `redisFanout({ client })` with a structural client
- [x] Client `relayTransport`: join with contiguous cursors; pages applied strictly in order through a promise chain and the gap-rule holdback; **push-outstanding after the last page**; keepalive deadline at 2.5× re-armed on every frame (a hello-less relay arms nothing); reconnect backoff, permanent on a version refusal; `webSocketDial` for the platform WebSocket
- [ ] `token()` / `visibleAt()` with `VisibilityLost` on lineage change; `putBlob` / `fetchBlob` verified (with E13)
- [ ] `Relay` transport class declaring `visibility` and `blobs`

- [x] Handshake versioning from day one: `join { supportedProtocolVersions }` → `hello { selectedProtocolVersion, keepalive, epoch }` | `error` then close (D14)
- [x] A second `join` from the same peer id disconnects the old socket **first** — never two sockets for one peer, never a silent room switch
- [ ] Persist what each remote peer had, keyed by the thing that persists (device key), not the connection — a re-meeting skips the round trip
- [x] The relay forwards grants first and byte-identical (the received frame bytes), never re-encoded (E07 task 4)

## Watch out

- Every raw `ws.send` is a future hang. The 100k-event load rig found a joiner that received exactly the buffer's worth and hung forever.
- A dropped row patch (E13) is unrecoverable — always queue it.
- The first `join` binds a socket to a room; a second must not silently switch rooms and leak the socket.
- ~~The relay is in memory until E04 lands~~ — `startRelay` is durable by default; only a caller-supplied memory store is ephemeral, on purpose.
