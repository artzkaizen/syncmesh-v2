## Goal

An engine that turns a local write into an event (recorded changes, one HLC stamp, one sequence number), folds events into kernel state, notifies once per batch, dedups on receipt, and can tell another engine exactly what it lacks. Plus a two-engine `Link` with an offline switch — the anti-entropy protocol in miniature.

## Decisions needed

D02 error model (mutate returns a `Result`)

## Tasks

- [x] `SyncEvent { v, id, peerId, seqNum, hlc, procedure, partition?, changes }` and `Change` (insert/update/delete — `Change` is the kernel's)
- [x] `engine.mutate(label, tx => …, { partition?, local? })` — a recording `Tx`; empty → `Err(EmptyMutation)`, nothing ticks
- [x] Sequence allocation that re-reads the store's `lastSeq` (a sibling tab may have allocated)
- [ ] `fold(events, source)` → `foldOne` each, emit **one** `FoldBatch { writeTables, writeKeys, source, eventCount }`
- [x] `receive` / `receiveBatch` with dedup by `${peerId}-${seqNum}`; own events skipped
- [x] `cursors()` → `Map<peer, maxSeq>`; `eventsSince(theirCursors)`
- [x] `EventStore` port (append, has, all, lastSeq, maxHlc — async per D05-B; allSince / compactBelow / snapshot slot arrive with their tasks) + `MemoryEventStore`
- [x] `onFoldBatch`, `onOutbound`, `onError` — each returns an unsubscribe
- [x] `Link(a, b)` — forwards `onOutbound` both ways, `setOnline`, `catchUp()` symmetric by cursors
- [x] `undoDepth` + `revert(eventId)` writing a compensating event **in the original event's partition**

- [x] The per-peer sync step as a **pure function pair** — `(state, doc) → (state, msg?)` and `(state, doc, msg) → (state, doc)` — no I/O, no clock; `Link.catchUp()` is the loop that feeds them to each other
- [x] An explicit per-peer `inFlight` flag: never generate a second batch to a peer until the first is acknowledged; cleared on receive. Stops a reconnect storm re-sending the same batch three times
- [x] Telemetry seam (D17, moved from E00): one discriminated union, every subsystem emits `{ type, sizes, durationMillis }`, the top object re-emits. Build it here because the engine emits the first event

## Watch out

- One notification per batch, not per event. E10 maintains live queries from `writeKeys`; if they are not exact, queries drift.
- `revert()` in the exploration emitted a partition-less event and failed validation whenever partitions were on — undo had never worked outside single-partition tests.
- Local-only events (`local: true`) must count in their own sequence namespace so they never consume a synced number.
