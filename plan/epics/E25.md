## Tasks

- [x] Durable Object class: `fetch` upgrade → `join`; `webSocketMessage / Close` → `RelayRoom`; storage via the DO SQLite driver; hibernation. `relayDurableHost` is the three callbacks and the wiring is the `@example`; the `fetch` half is the host's four lines, not this package's
- [ ] Rivet actor — needs the async driver port (D05)
- [x] An embedded example: `startRelay()` + `createMesh({ stateStore })` in one existing backend process — `examples/src/embedded/backend.ts` (`openBackend`), run by `server.ts` and by `examples/src/__tests__/embedded.test.ts` (a phone's write lands in the backend's own `notes` table read with plain Drizzle; a second phone catches up; a wrong invite is refused; a restarted backend answers from its table). The test found the example's Drizzle opening the log file instead of the state file, where the rows live — fixed 2026-11-07
- [x] A `docker compose` for the fleet shape — `examples/src/fleet/compose.yaml` (three relays, nginx, Postgres `LISTEN/NOTIFY` as the fanout: `postgresFanout` replaced the Redis one behind the same `Fanout` port, `df56207`). The shape is proved in-process by `examples/src/__tests__/fleet.test.ts`; the compose file itself is not run by CI

## Watch out

- The platform routes every socket for a room to one actor — that is what removes the fleet problem. Do not add Redis to the actor shape.
