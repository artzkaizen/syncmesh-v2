## Goal

Old and new app versions coexist on one mesh: contiguous cursors so a hole is visible, a knob for unknown events, quarantine with retry after upgrade, and an additive-only rule instead of a migration system.

## Decisions needed

D13

## Tasks

- [x] **D22-A: the opaque change.** `Change` gains `{ kind: "unknown", tag, table, key, data }`, `decodeChange` keeps an unrecognised tag whole instead of refusing the event, and `encodeEventCore` puts it back byte for byte — the round trip has to be exact or the signature stops covering what the later build reads. `foldable()` is the narrowing predicate that pairs with `unfoldableKind`, so the one shape a fold cannot handle cannot reach one by accident: `applyChange` takes `FoldableChange`, and every other call site the compiler surfaced had to say what it does with an unknown rather than fall through to an `else`.

  This is what finally lets E18's parking machinery fire for the case it was built for. Before it, the codec refused the event, both transports read a wire error and dropped it, and `unknownHandling`, `onQuarantine` and `retryQuarantined()` could never see the thing they exist for. Now it reaches `admit`, parks as `unknown-kind`, and holds the author's cursor open at its own sequence while later events keep arriving — pinned by a test that goes through the codec rather than forging a kind with a cast, one that folds the same run in two orders and compares digests, and one at the relay proving it is stored and re-served byte-identically.

  Two smaller calls the union forced. An unknown change **matches** an interest whose predicate cannot be evaluated against it, because dropping it at the sender would put it behind a coverage saying it was accounted for and nothing would offer it again. And nothing here can author one: the transaction API has no way to express it, and the probe refuses it below that anyway.

- [x] Contiguous cursors `{ contiguous, ahead }` per author replacing MAX; `cursors()` still returns the contiguous number; relay follows — **first, and everything else waits on it**: with MAX cursors a dropped event leaves a hole the cursor advances past, so parking an event a build cannot read is impossible (D13)
- [x] `unknownHandling: "warn" | "ignore" | "fail"` on `createMesh` — per-mesh config, never a per-event decision: two peers choosing differently is the divergence the additive rule exists to avoid
- [~] Quarantine store — typed reason, `engine.quarantine()`, `retryQuarantined()`, `onQuarantine()`, bounded per reason with loud eviction: all built. **Not built**: the *verbatim bytes*. A parked entry is the event as `decodeEventCore` read it, so a newer build's added key is already dropped and the kept signature no longer covers a re-encode of what is left; carrying the bytes needs `StoredEvent` to keep the core it arrived as. And the `unknown-kind` bucket has no wire path into it — `decodeChange` refuses an unknown kind and the transports drop the event before `admit` runs
- [x] The additive-only rule, documented and lint-checked; renames are adds
- [~] Then: `onConflict("counter")` / `("set")` — the kernel strategies, the wire change kinds and their property tests landed with E26; what is missing is the schema surface (`t.counter()`, `t.set()`), so no app can declare one yet — one new change kind carrying a delta, kernel merge, a frozen vector; old peers park it

## Watch out

- MAX cursors hide a dropped event forever. Contiguous first, or nothing else here works.
- A parked event must not advance the cursor past itself — on the wire. It must not gate delivery
  either: a receiver walks an author's run using the cursor *and* what it holds above it, or one
  refusal no upgrade reverses stops that author's stream for the life of the device.
- A relay's advertised cursor is the same contract. Counted as a MAX, or over entries its
  catch-up cannot serve, it names a position nothing will ever fill.

## Tests

- A newer peer emits an unknown change kind; the older parks it, does not advance, admits it after `retryQuarantined()`, converges. Property: a mid-stream version bump converges to the same state as an all-current schedule. Fuzz: sustained forged load never grows quarantine past the cap.

## Done when

Two app versions on one mesh converge, and the older one shows the newer's rows minus the columns it cannot read.
