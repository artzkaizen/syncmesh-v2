## Goal

The relay is the only component an attacker can reach; make it bounded. Give the system one telemetry seam. Version the handshake before anyone depends on it.

## Decisions needed

D14, D17

## Tasks

- [x] Relay: origin allowlist, `maxFrameBytes`, backlog ceiling that **closes**, per-socket token buckets, `verifyJoin(req, room)` — all built and forwarded by both hosts. Two classes and not three: `TrafficClass` is `event | blob`, since a `desire` frame is not a thing this wire has. Room-log and blob retention caps (`RelayRetention.keepEventsFor` / `maxBlobBytes`, `retention.ts`) and idle-room eviction (`idleAfter`, `rooms.ts`) are built and tested (`retention.test.ts`, `rooms.test.ts`)
- [x] A client can pin the relay's key: `relayKey` on `relayTransport` / `webSocket()`; a hello from any other key is a permanent refusal; `startRelay` hands the key out as `RunningRelay.peerId` (D36 follow-up)
- [ ] Write the confidentiality posture into RFC-0017: `verifyJoin` + per-partition encryption, or 'a room name is a bearer secret', in those words
- [~] `onEvent` with a discriminated union on engine, mesh and relay — all three layers now emit it (D17). The inspector that consumes it is not built, and D17 deliberately left open whether relay variants may carry peer identity; none do today
- [x] Handshake versioning (D14) with an additive vector
- [ ] Versioned row patches (`epoch` + monotone id, resnapshot-on-gap) for E13's row path
- [ ] `mesh.transports.add / remove`, `mesh.start()` symmetric with `stop()`

- [x] A relay join proves the key it names: `challenge` frame (tag 19), signed v2 join, `unproven` refusal before the seat is taken; Durable Object host keeps the nonce in the resume script (D33)
- [x] Clock drift bounded on every mesh: `DEFAULT_MAX_DRIFT` clamps the clock and arms the `ClockAhead` rung; `clockDrift` overrides (D34)
- [x] The relay link runs the link handshake (D33 option C → D36): protocol v3, identity from the hello, every frame sealed per socket, the challenge kept only for rooms that list 2; Durable Object keeps the link state in its resume script
- [x] Conformance vectors for every wire, not only event cores: session frames + length framing (`frame-vectors.json`), the link handshake and a sealed frame (`handshake-vectors.json`), relay control frames tags 8–19 (`relay-vectors.json`), the join proof (`join-vectors.json`), checkpoint certificates with their rows (`checkpoint-vectors.json`) — the contract a second implementation is measured against
- [x] D35: `crates/syncmesh-core` passes the wire vectors byte for byte and verifies every other frozen envelope (2026-09-26); next Rust slices: grant/receipt/account/checkpoint cores, then frames + join proof + handshake
- [~] D37: `crates/syncmesh-client` — the device in Rust, sans-IO: engine (sign at `mutate`, dedup, fold, quarantine, coverage), memory and SQLite stores, the D36 relay link as a state machine (pinning, version refusal, challenge path for rooms listing 2, liveness, backoff, holdback, scoped coverage), an in-process room as the server half, presence (D16), blobs (D18), grant registry, and a tokio WebSocket driver behind a feature. Measured against the TypeScript relay and client live (`tests/interop.rs`) and against the in-process room with explicit clocks. Not yet: the policy ladder, local scope, radios
- [x] Vectors for the rest of the wire: BLE fragment headers (`fragment-vectors.json`), feed certificates and chunks (`feed-vectors.json`), sealed payloads, sealed cores and wrapped keys (`sealing-vectors.json`), the presence core (`presence-vectors.json`), the Durable Object resume script (`resume-vectors.json`) — every byte a second implementation has to reproduce now has a frozen worked example

- [x] `announce` separate from `access` in the relay's posture: a server mode that never announces rooms and only serves what is explicitly requested (automerge's share policy vocabulary, applied to `verifyJoin`)

## Watch out

- Any socket can currently join any room and pull the whole log. Decide the posture; silence is not one.

## Tests

- One test per limit; the load rig still passes; a `v: 2` client against a `minV: 3` relay is refused with a typed reason.

## Done when

A hostile client cannot make the relay spend unbounded memory or disk; a stalled socket is closed, not accumulated.
