## Goal

The relay is the only component an attacker can reach; make it bounded. Give the system one telemetry seam. Version the handshake before anyone depends on it.

## Decisions needed

D14, D17, D48 (relay telemetry stays anonymous; decided A, 2026-11-08)

## Tasks

- [x] Relay: origin allowlist, `maxFrameBytes`, backlog ceiling that **closes**, per-socket token buckets, `verifyJoin(req, room)` — all built and forwarded by both hosts. `TrafficClass` is `event | blob | fanout`: no `desire` frame exists on this wire, and `fanout` is what a socket's events cost the room rather than a frame class. Room-log and blob retention caps (`RelayRetention.keepEventsFor` / `maxBlobBytes`, `retention.ts`) and idle-room eviction (`idleAfter`, `rooms.ts`) are built and tested (`retention.test.ts`, `rooms.test.ts`)
- [x] The relay is bounded by default (gap audit №5–8): socket caps per process, per room and on open rooms (`maxConnections` / `maxRoomConnections` / `maxRooms`, 503 at upgrade — `host.test.ts`, `serve.test.ts`, `cloudflare-do/…/host.test.ts`); a byte-bounded backlog (`maxBacklogBytes`); fan-out metered per socket and per room (`rates.fanout` / `roomFanout` — `limits.test.ts`); durable hosts evict idle rooms after `DEFAULT_IDLE_AFTER` (`serve.test.ts`), and the blob store has a default ceiling (`retention-defaults.test.ts`). The room log alone stays unbounded unless `DURABLE_RETENTION` is opted into, and says so in `relay.retention.unbounded`
- [x] A client can pin the relay's key: `relayKey` on `relayTransport` / `webSocket()`; a hello from any other key is a permanent refusal; `startRelay` hands the key out as `RunningRelay.peerId` (D36 follow-up)
- [x] Write the confidentiality posture into RFC-0017: `verifyJoin` + per-partition encryption, or 'a room name is a bearer secret', in those words — D40, RFC-0017 "Confidentiality posture". Built: grant-gated rooms (`posture.trust`, the grant as the ticket after the hello, entitlement-scoped catch-up and live fan-out, `ungranted` / `revoked` / `regranted` refusals, `gated.test.ts`), the read gate on peer links with the `withheld` frame (`read-gate.test.ts`), hosted presets that refuse to start without `trust` or `open: true` and default `announce` off, and the issuer half of sealing (`createPartitionKeys`, `grants.rekey`). Blobs follow the same gate (D44): puts checked against the grant, fetches served by the partition the bytes were put into. A narrowed entitlement purges what the device may no longer read, log and doc logs and cached blobs included, keeping its own writes (D45, `engine.purge`, `createMesh({ onNarrowed })`). End to end: `client/src/__tests__/read-permissions.test.ts`, `client/src/__tests__/narrowing.test.ts`
- [x] `onEvent` with a discriminated union on engine, mesh and relay — all three layers emit it (D17). Relay variants carry no peer id, room name or event id (D48, decided A 2026-11-08): the doc comments cite it and `relay/telemetry.test.ts` pins it over a join, a catch-up, an event, a blob put and a get. The consumer is built (U2): `mesh.inspect.telemetry()` is a tap over the seam that the devtools source reads, and `mesh.inspect.why()` / `PolicyDenied.rule` + `because` give a policy verdict its why (`client/inspect-why.test.ts`, `engine/can.test.ts`, `policy/evaluate.test.ts`), and `engine.store.commit` taps the storage transaction behind every write and received batch (`engine/errors-telemetry.test.ts`). Not built: a tap on reads
- [x] Custody through a relay (D32's relay half, U17): receipts (session tag 7) and refusals (the relay's own control tag 22, because session tag 9 is `hello` there) are signed by the devices in a room, handed by the room to the author they name and to no other socket, and published to the room's other instances; in a grant-gated room a holder signs the run it was actually sent (`Coverage.held`), not its scoped cursor; frozen in `conformance/relay-vectors.json`, decoded in Rust (`relay_frames.rs`). React renders `refused-by` (`refusedBy`, `useRefusedBy`, plan/react-api.md G12). Tested in `relay/custody.test.ts` and, through `startRelay` and the ledger, `client/relay-custody.test.ts`. A device repeats a refusal once per seating of its author, which the room announces with `seated` (tag 23)
- [x] The relay room as a holder (U38, D28's relay half): a room given `custody` signs a receipt under its own key with its epoch as the incarnation, batched per author per `every`, opt-in and refused unless its key outlives a durable, untrimmed log; `detach` gates on `soleCustody()` (`relay/room-receipts.test.ts`, `client/relay-custody.test.ts`, `storage/detach.test.ts`)
- [x] Handshake versioning (D14) with an additive vector
- [x] Versioned row patches (`epoch` + monotone id, resnapshot-on-gap) for E13's row path. The `rows` frame (tag 34) carries an epoch and a version exactly one past the last. `createPatchStream` applies only a reset or the next version and reports anything else as a `gap`. The thin client then re-desires with `since`, and the socket's server windows (`createServerWindows`) answer with a reset into a new epoch. Frozen in `conformance/window-vectors.json` (D43); tested in `window/stream.test.ts`, `window/server.test.ts` and, over a real Postgres, `orpc/served-postgres.test.ts`. A patch may also carry a `failed` list (a ninth element, absent when empty): windows whose read did not run this time keep their rows and are read again, and the next patch naming them clears it (2026-11-08). A resync's `since` survives an `undesire` and a re-`desire` coalesced behind it, so the reset it asked for still comes (`window/server.test`)
- [x] `mesh.transports.add / remove`, `mesh.start()` symmetric with `stop()` — `start: false` boots the engine and opens nothing until `mesh.start()`; idempotent; after `stop()` a `MeshStopped` value; `transports.add` before start queues the medium (`client/mesh-transport.test.ts`, "runtime transports" and "start() symmetric with stop()")

- [x] A relay join proves the key it names: `challenge` frame (tag 19), signed v2 join, `unproven` refusal before the seat is taken; Durable Object host keeps the nonce in the resume script (D33)
- [x] Clock drift bounded on every mesh: `DEFAULT_MAX_DRIFT` clamps the clock and arms the `ClockAhead` rung; `clockDrift` overrides (D34)
- [x] The relay link runs the link handshake (D33 option C → D36): protocol v3, identity from the hello, every frame sealed per socket, the challenge kept only for rooms that list 2; Durable Object keeps the link state in its resume script
- [x] Conformance vectors for every wire, not only event cores: session frames + length framing (`frame-vectors.json`), the link handshake and a sealed frame (`handshake-vectors.json`), relay control frames tags 8–19 (`relay-vectors.json`), the join proof (`join-vectors.json`), checkpoint certificates with their rows (`checkpoint-vectors.json`) — the contract a second implementation is measured against
- [x] D35: `crates/syncmesh-core` passes the wire vectors byte for byte and verifies every other frozen envelope (2026-09-26); next Rust slices: grant/receipt/account/checkpoint cores, then frames + join proof + handshake
- [x] D37: `crates/syncmesh-client` — the device in Rust, sans-IO: engine (sign at `mutate`, dedup, fold, quarantine, coverage), memory and SQLite stores, the D36 relay link as a state machine (pinning, version refusal, challenge path for rooms listing 2, liveness, backoff, holdback, scoped coverage), an in-process room as the server half, presence (D16), blobs (D18), grant registry, and a tokio WebSocket driver behind a feature. Measured against the TypeScript relay and client live (`tests/interop.rs`) and against the in-process room with explicit clocks. The policy ladder is ported whole over the manifest as data (gap U3, `validate.rs`, `conformance/policy-vectors.json`), with each column's `check()` as the JSON Schema it says it accepts, `can()`, and local-only writes (`Engine::mutate_local`); the join exchange and D46's rejoin from state are `join.rs` and `rejoin.rs`, byte for byte against `conformance/snapshot-vectors.json` (gap U31). A port's check is never stricter than the function it says (D37). From #35's review, U34 (one cell order for a certificate, version 2), U36 (snapshots leave `local` tables out) and U37 (a relay's `retention` refusal held off, the install's floor kept in the log) are built in #43. Radios are built in #PR: a Rust peer link over any byte duplex (stream, message or BLE fragments), byte for byte with the TypeScript upgrader and bridge (`conformance/peer-link-vectors.json`), live against the TypeScript LAN and BLE links (`tests/peer_interop.rs`)
- [x] Vectors for the rest of the wire: BLE fragment headers (`fragment-vectors.json`), feed certificates and chunks (`feed-vectors.json`), sealed payloads, sealed cores and wrapped keys (`sealing-vectors.json`), the presence core (`presence-vectors.json`), the Durable Object resume script (`resume-vectors.json`) — every byte a second implementation has to reproduce now has a frozen worked example

- [x] `announce` separate from `access` in the relay's posture: a server mode that never announces rooms and only serves what is explicitly requested (automerge's share policy vocabulary, applied to `verifyJoin`)
