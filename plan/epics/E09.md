## Goal

One constructor. Collections with `create / update(draft) / delete / get / list / query / history`; atomic multi-collection `tx`; `can`; `revert`; capabilities surfaced from transports; reserved tables kept out of your namespace.

## Decisions needed

D02, D06, D10

## Tasks

- [ ] `createMesh({ schema, identity | peerId, account, store? | storeFor?, dataDir?, transports?, grants?, stateStore?, snapshotEvery?, undoDepth?, isAuthority?, now? })` — durable store by default
- [x] `mesh.<t>` verbs speak REST: `create` (pk from the row; recorded as `<t>.insert`, the wire's word), `update(key, patch | draft => …)` diffing and refusing empty, `delete`, `get(key)`, `list(options)` returning rows one-shot, `query(options)` as the same question in data form for `mesh.liveQuery`/`releaseQuery` and E10's hooks, and `history(key)` ordered by stamp, each revision's row the kernel's own fold
- [x] `mesh.tx(fn, { label? })` — one event, one partition; `CrossPartitionTx` refused *before* commit; `EmptyTx` (the engine's `EmptyMutation`); label derived from what was written
- [x] `mesh.can`, `mesh.revert` / `canRevert`, `mesh.stop()`, `mesh.running`, `mesh.engine`
- [ ] `mesh.internal` for reserved tables; `mesh.visibility`, `mesh.blobs` (typed `NoSuchCapability` when no transport has it), `mesh.corrections`
- [x] Every write returns `Result<…>` with the full error taxonomy; no optimistic overlay

- [ ] `mesh.flush()` — settles even when some saves fail (safe to await), with a concurrency cap the docs tie to the storage's constraining resource; `mesh.stop()` = flush, then close transports and stores
- [x] `mesh.transports.add(t)` / `.remove(name)` at construction time, not later — automerge has it from v1 — `transports: [...]` on `createMesh`; add/remove later deliberately absent
- [ ] `tooling/verify-node-consumer` (moved from E00, D01 watch-out): pack each publishable package, `npm install` it into an empty Node project, `import()` it with real `node`. Bun tolerates what Node rejects (extensionless imports, `bun:*` at top level); this is the test that catches it
- [x] `mesh.activate("org:x")` — the active instance per kind, set once by the org switcher; collections use it; nothing active → `Err(NoActivePartition)`; implied when the grant lists exactly one instance of a kind. No `partitions:` on `createMesh`: instances come from grants (`plan/use-cases.md`)
- [x] `mesh.can("books.update", row)` typed as `"table.action"`, answering from the same AST the receiver enforces, with a ready state while the grant loads (Permix ergonomics)

## Watch out

- `update` must write **only** changed columns — that diff is what makes field-level merge real.
- Reserved tables (`_policy`, `_corrections`) leaked into `mesh.collections` three times in the exploration; a test pinning the namespace caught it each time. Write that test first.
- `history()` scans the log (~63 ms at 50k events on SQLite) — a detail-view API, not a list API.
