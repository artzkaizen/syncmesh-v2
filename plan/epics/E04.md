## Goal

Durable event log and materialised state behind small ports, one SQLite implementation with N drivers, a durable platform default, and boot invariants that never let the clock regress.

## Decisions needed

D05 storage ports · D15 retention

## Tasks

- [x] `SqliteDriver` port — `run / all / get / transaction? / close?` (sync or async per D05)
- [x] **One** `sqliteEventStore(driver)`: schema, migration (add `partition` to old databases), `appendBatch` in one transaction, `allSince(floor)` pushed into SQL, `lastSeq`, `maxHlc`, `compactBelow`, snapshot slot
- [~] Drivers: `bun:sqlite`, `node:sqlite` and the Durable Object's `ctx.storage.sql` all ship and all run `driverTests`; sqlite-wasm over OPFS does not exist. Writing the three taught that almost nothing in a driver is the binding — SQLite has no boolean and no date type, so both bind as the integers the dialect writes and reads back; `transaction` wants `BEGIN IMMEDIATE`, because a deferred one takes its write lock at the first write and failing to take it there throws away work already done; the dialect tag and the promises the port returns are identical everywhere. All of it is `sqliteDriver(binding)` in the storage package now, and an adapter is the ~8 lines its binding genuinely calls differently. `ctx.storage.sql` is the one that stays hand-written: `sql.exec` refuses `BEGIN`, so it has no `transaction` at all and rides the object's turn instead.

  **A binding gets a package only when it ships with the runtime.** `node:sqlite`, `bun:sqlite` and `ctx.storage.sql` are versioned by the runtime carrying them: no second version matrix, no release of ours per release of theirs, so the package costs nothing to keep and stays honest by construction. A binding the app installs — `expo-sqlite`, `@op-engineering/op-sqlite`, `better-sqlite3` — gets none. Against the public `SqliteBinding` port it is eight lines the app can read in full, and the public `driverTests` certifies those eight lines exactly as well as it certifies ours; wrapping them would add a dependency, a version matrix and a release cadence and buy the app nothing. **React Native therefore ships without an adapter and is not missing one** — it is the case the rule was decided on; the worked `expo-sqlite` driver and the certification recipe are in `packages/storage/README.md`. So `adapters/` is at its final three SQLite entries and names *bindings that come free with a runtime*, not *platforms syncmesh supports*.

  **The browser is the hole this leaves, and only the browser.** sqlite-wasm over OPFS is the one target the eight-line rule does not dispose of: OPFS is synchronous only behind a sync access handle inside a dedicated worker, so a binding callable from the app's own thread is async and cannot be a `SqliteBinding` at all — `bindSqlite` is exported for precisely that driver, which still has to be written — and someone has to own the wasm build, the worker and the COOP/COEP story (D20 carries it under costs accepted). Until then the client's `defaultStores` returns `NoDefaultStore` on a browser, and the durable option there is `localStorageEventStore`: a log with no SQL under it, so state is a memory store rebuilt by replaying that log at every boot — the exact thing "boot = open, not replay" was for. That is a driver's worth of work, and where it would live is the one thing the rule above does not settle — a wasm build is an installed dependency like any other, and `adapters/` is closed. It blocks E09's browser demo, not this epic.
- [x] `LocalStorageEventStore` — corrupt log recovers empty **and** surfaces a typed error, and a damaged head no longer takes the *numbering* with it. The reported gap is closed: resetting `lastSeq`/`maxHlc` to zero made the device re-issue sequence numbers its peers already held under different ids, and `has()` then dropped every new event on every peer, silently, for the life of the device.

  A damaged head now keeps the surviving log's marks and discards only its contents — sound rather than optimistic, because `persist` runs before `outbound.emit` in the write path, so a sequence the log never recorded was never sent to anyone either. Where **both** keys are damaged nothing on the device can know where it had got to, only a peer holding its past can; that case reports `numberingLost` instead of quietly starting again at one.
- [x] `defaultStore({ name, dir })` — durable by platform; `memory()` explicit (bun adapter; the client picks per platform in E09)
- [x] `StateStore` port (`isEmpty / loadAll / loadCursors / commit(rows, cursors)`) + a SQLite implementation; boot = open, not replay
- [x] `snapshotEvery: N` → boot = snapshot + tail; compaction clamped to the persisted snapshot's coverage — subsumed by the always-current state store (D05/D15); `engine.compact` clamps to its persisted coverage
- [x] Engine boot reads `maxHlc()` and `lastSeq(peer)` before allocating anything
- [x] `bench/storage` — per-event vs batched append; boot time vs log size

- [x] Decide (D05) whether a six-method KV port (`load / save / remove / loadRange / removeRange / close?`) sits *under* the SQLite store so IndexedDB / DO-KV / R2 are ~80-line adapters — cost: `allSince(floor)` needs a range query a KV port cannot express — decided against in D05; the floor runs in SQL via `json_each`
- [x] Size-based compaction trigger alongside `snapshotEvery`: compact when `incrementalBytes >= snapshotBytes || snapshotBytes < 1 KiB` — closer to what actually costs at boot than a count
- [x] A sequence-guarded 'last saved' marker — not needed: coverage is monotone and commits with its rows (D15); the persisted compaction floor guards the corrupt-cache case instead (automerge's `SavedHeads`): a compaction that started before an incremental save and finished after it must not clobber the newer heads. Needed the moment saves are async

- [x] `bench/` (moved from E00): create it with `bench/storage` as the first benchmark

## Watch out

- `maxHlc`/`lastSeq` wrong → the clock regresses → new events stamped below ones peers already saw → silently discarded as stale. Invisible.
- The two SQLite stores in the exploration drifted: one migrated old databases, one did not, and the missing migration corrupts every signature on re-ship. One store, N drivers.
- `saveSnapshot` must copy synchronously — the caller's object keeps mutating after the call.
- A memory default silently loses every write on restart. Durable by default.
