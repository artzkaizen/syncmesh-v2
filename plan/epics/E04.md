## Goal

Durable event log and materialised state behind small ports, one SQLite implementation with N drivers, a durable platform default, and boot invariants that never let the clock regress.

## Decisions needed

D05 storage ports · D15 retention

## Tasks

- [x] `SqliteDriver` port — `run / all / get / transaction? / close?` (sync or async per D05)
- [ ] **One** `sqliteEventStore(driver)`: schema, migration (add `partition` to old databases), `appendBatch` in one transaction, `allSince(floor)` pushed into SQL, `lastSeq`, `maxHlc`, `compactBelow`, snapshot slot
- [ ] Drivers: `bun:sqlite`; sqlite-wasm over OPFS (browser, worker); `node:sqlite` or better-sqlite3; Durable Object `ctx.storage.sql`
- [ ] `LocalStorageEventStore` — corrupt log recovers empty **and** surfaces a typed error
- [ ] `defaultStore({ name, dir })` — durable by platform; `memory()` explicit
- [ ] `StateStore` port (`isEmpty / loadAll / loadCursors / commit(rows, cursors)`) + a SQLite implementation; boot = open, not replay
- [ ] `snapshotEvery: N` → boot = snapshot + tail; compaction clamped to the persisted snapshot's coverage
- [x] Engine boot reads `maxHlc()` and `lastSeq(peer)` before allocating anything
- [ ] `bench/storage` — per-event vs batched append; boot time vs log size

- [ ] Decide (D05) whether a six-method KV port (`load / save / remove / loadRange / removeRange / close?`) sits *under* the SQLite store so IndexedDB / DO-KV / R2 are ~80-line adapters — cost: `allSince(floor)` needs a range query a KV port cannot express
- [ ] Size-based compaction trigger alongside `snapshotEvery`: compact when `incrementalBytes >= snapshotBytes || snapshotBytes < 1 KiB` — closer to what actually costs at boot than a count
- [ ] A sequence-guarded 'last saved' marker (automerge's `SavedHeads`): a compaction that started before an incremental save and finished after it must not clobber the newer heads. Needed the moment saves are async
- [ ] `runDriverTests(openDriver)` passes for every driver
- [ ] `bench/` (moved from E00): create it with `bench/storage` as the first benchmark
- [ ] `packages/testing` (moved from E00): `runDriverTests(openDriver)` as a shipped suite every driver — and every third-party driver — runs; runner-neutral so it does not depend on `bun:test`

## Watch out

- `maxHlc`/`lastSeq` wrong → the clock regresses → new events stamped below ones peers already saw → silently discarded as stale. Invisible.
- The two SQLite stores in the exploration drifted: one migrated old databases, one did not, and the missing migration corrupts every signature on re-ship. One store, N drivers.
- `saveSnapshot` must copy synchronously — the caller's object keeps mutating after the call.
- A memory default silently loses every write on restart. Durable by default.
